## 0. 为什么有 v0.3

我们已经拿到**阿里云 DashScope（Qwen）API Key**，调研后发现：

1. **Qwen3-VL** 是当前**唯一明确公开为 GUI Agent 专项训练**的可用模型（DeepStack 多级 ViT、像素级理解、PC/移动端 GUI 操作）
2. 官方课题 §4.1 明确推荐 **Qwen-VL** 作为可选 VLM
3. **政治均衡**：Qwen 主、豆包 2.0 Pro 互补，不绑定单一供应商
4. **答辩亮点**：评测报告里能直接出 **"Qwen3-VL vs 豆包 2.0 Pro 在飞书桌面 GUI 上的对比"**，是非常漂亮的差异化

因此 v0.3 把主模型从"豆包 2.0 Pro 单轨"升级为 **"Qwen 主、豆包 备" 双轨制**。

## 1. 主模型方案变更

### 1.1 新选型表（替换 v0.2 §5.1 主 VLM 行）

| 模块 | 主选 | 备选 | 理由 |
|---|---|---|---|
| 主 VLM（Planner / Grounder / Verifier） | **Qwen3-VL-Plus**（qwen3-vl-plus，DashScope） | 豆包 2.0 Pro（doubao-seed-2.0-pro） | GUI Agent 专项训练 + 像素级 grounding + 256K 上下文 + 已有可用 Key |
| 轻量 fallback | qwen3-vl-flash | doubao-seed-1-6-251015 | 主模型超时/限流时切换 |

### 1.2 模型角色分配（同 v0.2 架构不变）

| 角色 | 模型 | thinking |
|---|---|---|
| Planner | Qwen3-VL-Plus | enable_thinking=True（多步规划） |
| Grounder | Qwen3-VL-Plus | enable_thinking=False（快速定位） |
| Verifier L3 | Qwen3-VL-Plus | enable_thinking=False（语义判断） |

### 1.3 Reasoning 档位映射（v0.2 §5.3 升级）

不同 Provider 的 reasoning 档位字段不一样，由 `LLMClient` 子类各自适配：

| ReasoningLevel | Qwen3-VL（DashScope） | 豆包 2.0 Pro |
|---|---|---|
| MINIMAL | `enable_thinking=False` | `thinking={"type":"minimal"}` |
| LOW | `enable_thinking=True` | `thinking={"type":"low"}` |
| MEDIUM | `enable_thinking=True` + 强提示 | `thinking={"type":"medium"}` |
| HIGH | （CUA 禁用） | `thinking={"type":"high"}`（禁用） |

> Qwen 思考模式只有二态 on/off，所以 LOW/MEDIUM/HIGH 都映射到 enable_thinking=True；档位差异通过 prompt 引导。后续若 Qwen 支持多档可平滑升级。

## 3. 切换主模型的方法（用户视角）

```bash
# 默认 (有 DASHSCOPE_API_KEY 自动选 Qwen)
echo "DASHSCOPE_API_KEY=sk-xxx" >> .env

# 显式选豆包 (有 ARK_API_KEY 时)
echo "LLM_PROVIDER=doubao" >> .env
echo "ARK_API_KEY=xxx" >> .env

# 双 Key 同时配置 → 评测对比模式
# LLM_PROVIDER 控制主模型，另一个自动作为 fallback
```
