## [20:55] Solution + Pattern: TuriX 上游 bug fix - done action schema/handler 脱节

**Type**: solution
**Tags**: `bug`, `architecture`, `dependency`
**Related**: [[2026-04-27#optimization-actor_llm-切-qwen3-vl-flash-降低-3-5-倍延迟]]

切 flash 后 lark_im_search 还是失败, 但根因不是慢, 而是任务**实际成功后无法正常 done**:

- Step 4 Brain 已经看到 "hello: Hello!" 搜索结果, 判定 task complete
- Actor 输出 `{"done":{"text":"Task completed..."}}` (按 DoneAction schema)
- Controller `Error executing action done: got an unexpected keyword argument 'text'`
- Agent 不知道任务已结束, 继续 loop 4 次直到 max_steps=8 报 `Failed to complete task`

**根因**: TuriX 上游 schema/handler 脱节
- `views.py` L9: `class DoneAction(BaseModel): text: str`  ← LangChain 把 schema 注入 LLM
- `service.py` L161: `param_model=NoParamsAction` + `async def done()` ← handler 无参数

**为什么 4-26 plus 跑通过**: doubao/plus 类"宽松"模型经常省略 schema 里的可选字段, 输出 `{"done":{}}` 巧合能跑. flash 严格按 schema 输出 `{"done":{"text":"..."}}` 必中招.

**修法** (3 行 patch in `controller/service.py`):
- import DoneAction
- `param_model=DoneAction` (替代 NoParamsAction)
- `async def done(text: str = "")` (向后兼容空调用)

**Pattern 沉淀**:
- **诊断 CUA agent "max_steps 失败" 时, 第一时间看是不是 done action 没成功调**, 不是模型不会判 complete
- **vendor 上游代码时遇到 schema/handler 脱节, 优先修 handler 接受 schema (向后兼容), 不要改 schema (会影响 LLM prompt)**
- **flash vs plus 行为差异**: flash 严格按 schema, plus 宽松省略可选字段; 写 schema 时假设最严格的模型也会全字段输出

**FAQ Q4 合规**: 修上游 bug 不是自研功能, 已在代码加 `[LarkVision patch 2026-04-27]` 注释 + UPSTREAM.md §4.3 详细登记.

**Status**: ✅ verified (Controller 实例化成功 + done 正常注册; 待用户重跑确认)

## [18:10] Pattern: vendor 子目录 + 自研外挂式补强 = 站在巨人肩膀上的最优工程结构

**Type**: optimization
**Tags**: `architecture`, `refactor`

二开开源项目时的最优工程结构（赛事场景）：

1. **物理 vendor 到子目录**（如 `larkvision/`），去掉上游 `.git`/`.venv`，锁定 commit hash
2. **保留上游 `LICENSE`** + 写自己的 `UPSTREAM.md` 标注来源/commit/差异/致谢
3. **主仓的代码是"外挂式补强"**，不去 fork 上游主流程，只做上游做不好的事
4. **主仓 pyproject.toml 只装补强模块依赖**，上游用自己的独立 venv（避免 LangChain 全家桶污染主仓）
5. **`tool.ruff` 加 `exclude = ["larkvision"]`**：不 lint 上游代码
6. **bench 用例 + lark_skills 是自研 IP 沉淀的最佳载体**：YAML schema 自定，写一份用一份，决赛时这部分就是评委看的"自研工作量"

**Before**: 完全自研 = 时间不够 / 完全 fork = 没有创新点亮点  
**After**: vendor + 外挂补强 = 既站在巨人肩膀又有清晰的自研边界

**Status**: ✅ verified
