## [18:10] Pattern: vendor 子目录 + 自研外挂式补强 = 站在巨人肩膀上的最优工程结构

**Type**: optimization
**Tags**: `architecture`, `refactor`

二开开源项目时的最优工程结构（赛事场景）：

1. **物理 vendor 到子目录**（如 `larkvision/`），去掉上游 `.git`/`.venv`，锁定 commit hash
2. **保留上游 `LICENSE`** + 写自己的 `UPSTREAM.md` 标注来源/commit/差异/致谢
3. **主仓的代码是"外挂式补强"**，不去 fork 上游主流程，只做上游做不好的事
4. **主仓 pyproject.toml 只装补强模块依赖**，上游用自己的独立 venv（避免 LangChain 全家桶污染主仓）
5. **`tool.ruff` 加 `exclude = ["larkvision"]`**：不 lint 上游代码
6. **bench 用例 + lark_skills 是自研 IP 沉淀的最佳载体**：YAML schema 自定，写一份用一份，决赛时这部分就是评委看的"自研工作量"

**Before**: 完全自研 = 时间不够 / 完全 fork = 没有创新点亮点  
**After**: vendor + 外挂补强 = 既站在巨人肩膀又有清晰的自研边界

**Status**: ✅ verified
