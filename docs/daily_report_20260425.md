# 第一周期日报定稿（2026-04-23 至 2026-04-25）

## 一、核心产出

本周期完成了 CUA-Lark 项目的第一版产品方案、系统架构和可运行代码骨架，并在今天把项目推进到了真实桌面联调阶段。当前已经在用户本机完成了 macOS 预检打通，真实跑通了 Feishu 搜索、云文档、日历三个单步动作，同时识别并验证了首个真实异常场景：应用推荐安装弹窗，确认其可通过点击右上角关闭按钮恢复，并已补齐带恢复动作的 Docs / Calendar 组合用例和最小多步 Calendar 流程模板。

## 三、过程复盘与沉淀

### 1. 这周主要搞定了哪些具体环节？用了什么方法或工具辅助？

主要完成了三部分工作。第一部分是把赛题目标拆成可落地的五层架构：感知、规划、执行、验证、评测，并同步建立了项目仓库和基础运行链路。第二部分是完成了 macOS 原生执行器、截图适配器、运行产物落盘和批量验收入口，使项目具备从 dry-run 到真实桌面联调的基础设施。第三部分是围绕飞书桌面端做真实联调，先后打通了 macOS 权限预检、窗口相对坐标点击、真实单步动作验证，并针对推荐安装弹窗形成了第一版异常恢复方案，同时把恢复动作正式接入 Docs / Calendar 组合流程和最小多步模板。

### 2. 过程中有没有遇到什么特别不顺、卡住很久的情况？后来是怎么破局的？

最大的阻塞来自两处。第一处是 macOS 权限：虽然代码侧已经具备真实点击和截图能力，但实际执行进程没有获得 Screen Recording 和 Accessibility 权限，导致截图和窗口读取都失败。最终通过区分“当前会话代执行宿主”和“用户本机真实执行宿主”，把权限问题定位清楚，并以本机终端为真实执行入口解决。第二处是飞书真实页面中的推荐安装弹窗。起初假设按 `Escape` 可以关闭，但实际验证发现无效；后续通过直接操作 UI 验证，确认右上角关闭按钮才是更可靠的恢复路径，从而把异常处理策略从假设修正成了实测结论。

### 3. 有没有什么你觉得这次写得特别顺，或者下次还能直接复用的东西？

这次最可复用的是两类沉淀。第一类是工具链沉淀：`--doctor macos` 预检、`reports/runs` 产物目录、window-relative 坐标模板和批量验收命令，这些后续都可以直接复用。第二类是方法论沉淀：对真实桌面 Agent，不再只看“动作是否执行”，而是把“权限是否到位、窗口是否可见、弹窗是否阻塞、恢复路径是否有效”一起纳入测试闭环，这套排障方式后面做 M2 多步流程时会非常有用。

## 四、本周随手记

这次最重要的转折点，是项目从“dry-run 骨架可跑”进入了“真实飞书桌面可操作”。从比赛角度看，这比继续扩散功能面更有价值，因为它证明了视觉驱动桌面 Agent 的主链已经成立。接下来最合理的推进方式，不是盲目加更多功能，而是围绕真实多步流程、异常恢复和展示稳定性继续收口，让 Demo 更像一个成熟的测试产品而不是几个独立脚本。今天已经先把“真实单步 + 异常恢复 + 最小多步模板”这条主线收住，为下一阶段继续做创建文档、创建日程等真流程打好了底。
