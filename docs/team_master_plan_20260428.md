# CUA-Lark Team Master Plan

版本：`v1.0`

日期：`2026-04-28`

状态：`基于最新 PRD 的总分工与总排期文档`

## 1. 总目标

本次比赛版在 `2026-05-07` 前的唯一核心目标是：

1. 跑通六个飞书子产品的基础 demo
2. 跑通至少两到三条跨子产品联动链
3. 跑通一个最终整合主工作流 demo
4. 做出灵动岛 / 主 UI 的展示壳

当前阶段不以：

1. PPT
2. 长文档包装
3. 额外答辩材料

为第一优先级。

当前阶段只以：

1. 子产品主链
2. 联动链
3. 最终整合 demo
4. `3.3` 进阶能力的有余力加深

为第一优先级。

## 2. 当前产品口径

基于最新 PRD，产品定义为：

**CUA-Lark OPC Mode = 面向 OPC 超级个体的飞书内部协作 AI 中枢。**

本期明确约束：

1. 只做飞书内部子产品联动
2. 主产品域是：
   - `IM`
   - `Calendar`
   - `Docs`
   - `VC`
   - `Base`
   - `Mail`
3. 主执行环境优先：
   - `飞书浏览器版`
   - `浏览器沙箱`
4. `5月5日` 前必须至少完成：
   - `1` 条核心工作流
   - 覆盖 `2` 个及以上子产品联动

## 7. 当前建议主工作流

本阶段最值得整合的主工作流建议是：

| 工作流 | 主负责 | 协同 | 目标 |
| --- | --- | --- | --- |
| `IM -> Calendar -> Docs` | 王泽 | 董圣娇、钟梓文 | 体现沟通到建会到文档沉淀 |
| `Calendar -> Docs -> VC` | 董圣娇 | 王泽、钟梓文 | 体现会议到文档到视频会议联动 |
| `Docs / Base -> Mail` | 钟梓文 | 王泽、董圣娇 | 体现信息沉淀到结构化记录再到邮件触达 |

推荐最终整合主工作流优先考虑：

1. `IM -> Calendar -> Docs`
2. 或 `Calendar -> Docs -> VC`

这样最贴近当前比赛要求和演示价值。
