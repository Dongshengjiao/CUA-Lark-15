## 三、过程复盘与沉淀

### 1. 这周主要搞定了哪些具体环节？用了什么方法或工具辅助？

本周期主要推进了两条真实业务流。第一条是 `Calendar`：通过真实界面探查和多轮联调，定位到了 `创建日程` 按钮、标题输入框和保存按钮，先跑通了草稿流程，再完成了最小真实创建。第二条是 `IM`：基于当前活动会话，完成了消息输入框聚焦、草稿清空和消息草稿输入的真实验证。工具上，继续沿用桌面 CUA 的执行器、截图链路、窗口相对坐标模板和运行产物落盘机制，同时补上了轻量观察校验，让核心 M2 用例在“动作成功”之外，还能附带前台窗口状态和截图产物证据。

### 2. 过程中有没有遇到什么特别不顺、卡住很久的情况？后来是怎么破局的？

本周期最典型的问题出现在 `Calendar` 的重放稳定性上。首次真实创建日程虽然成功，但后续重复运行时，如果前台残留了一个 `创建日程` 窗口，原本依赖主窗口坐标的 case 就会在“切到日历”和“打开创建窗口”两步上失稳。后来的解决方式是把“前台是否已经存在创建窗口”纳入流程判断：如果前台窗口标题包含 `创建日程`，就先安全关闭残留窗口，再回到主窗口重新执行创建流程。另外，对窗口相对坐标解析加了小幅重试，也进一步降低了慢加载带来的波动。

### 3. 有没有什么你觉得这次写得特别顺，或者下次还能直接复用的东西？

这次最值得复用的是两类沉淀。第一类是 `M2` 级别的真实业务模板：`Calendar` 的创建流程和 `IM` 的草稿流程已经从“单步点击”提升到了“多步串联”，后续扩展参与人、描述、发送确认都能直接在这套模板上继续叠加。第二类是稳定性方法：通过前台窗口判断、残留窗口清理、窗口相对坐标、运行产物复盘，以及轻量观察校验这几步，可以比较系统地把桌面 Agent 的“能跑一次”推进到“可以多次重放、也能留下更清晰的验证证据”。
